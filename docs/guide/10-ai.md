# 10. AI

## What it's for

AI in FollowUp is a helper you call when you want it:

- an **assistant** that answers questions about your work and makes changes **with your approval**;
- **writing help** for tasks and emails;
- **inbox triage** that sorts new mail.

It's **optional**, uses **your own** account with an AI provider (or a local model that never leaves your PC), and sends only what each request needs.

## Setting it up

**Settings → AI:**

| Setting | Options |
|---|---|
| **Provider** | **Claude** (Anthropic), **OpenAI**, or **Local (Ollama)** |
| **Claude model** | Claude Opus 5.5 (recommended), Sonnet 5.5 (faster, cheaper), Haiku 5.5 (fastest, cheapest), Fable 5.1 (most capable, most expensive) |
| **OpenAI model** | Any model name your key can use (default `gpt-5`) |
| **Ollama** | **Server address** (default `http://localhost:11434`) and **model** (one you've pulled, e.g. `llama3.1` or `qwen2.5`; the assistant needs a model that supports tool use) |
| **API key** | Paste your Anthropic key (console.anthropic.com → API keys) or OpenAI key, then **Save key**. Use **Replace** or **Remove** later. Keys are encrypted with Windows DPAPI; the window only ever learns *whether* a key is saved. |
| **Thinking effort** | Low / Medium / High: higher gives better answers in chat and writing, but is slower and costs more. Sorting email and parsing Quick add always use Low. |
| **Test connection** | Sends a tiny request and reports *Connected to …* or the exact problem. |
| **Sort new email automatically** | Off by default. When on, each new inbox email is sent to the provider and labelled (see [Inbox triage](#inbox-triage)). |
| **Sort current inbox now** | Labels the 30 most recent unlabelled inbox threads once. |
| **Usage this month** | Tokens in and out, calls per feature, and an **estimated cost** for Claude models. |

## The assistant (`Ctrl+J`)

![AI assistant](../images/assistant.png)

Open it with `Ctrl+J`, the sidebar's **AI assistant**, or **Ask the assistant…** in a task. Type naturally:

- *"What's overdue and what's due this week?"*
- *"Summarise my emails from Priya."*
- *"Create a task to send the contract to Northwind, due Friday, high priority."*
- *"Move all my Website Launch tasks due this week to next Monday."*
- *"How much time did I spend on Acme last week?"*
- *"Draft a reply to Daniel saying Thursday 10:00 works."*
- *"Start the Polite nudge follow-up on my proposal to Jordan."*

### What it can do

| Reads automatically | Changes only after you approve |
|---|---|
| `list_workspace` — spaces, folders, lists, status names | `create_task` (also subtasks) |
| `search_tasks` — by words, list, due window, done or not | `update_task` — title, status, priority, due date |
| `get_task` — description, subtasks, checklists, comments, linked emails, time | `add_comment` |
| `my_work` — overdue, today, next 7 days | `create_event` — calendar event |
| `search_emails`, `get_email_thread` | `create_reminder` |
| `list_events` — calendar | `log_client_interaction` — record a call, chat, meeting or event with a client |
| `time_report` — tracked time per task | |
| `list_goals`, `list_follow_ups` — emails waiting for a reply from you or them | |
| `find_client` — a company, its people and recent history | |

**Drafts, never sending:** `draft_email` opens **Compose** with the draft for you to review and send. The assistant **never sends email itself**.

### Approval cards
When the assistant wants to change something, the chat shows a card for each change: what will happen ("Create task 'Send the signed contract to Northwind' in Clients, due 2026-10-23, high priority"), with **Details** for the exact input.

- **Approve** or **Decline** each card, or **Approve all** / **Decline all**.
- Typing a new message instead counts as **declining** the open cards.
- Declined actions are reported back to the assistant, which won't retry them unless you ask.

### Conversations
- The header lists past conversations; **＋** starts a new one, and the bin deletes one.
- **Stop** interrupts a reply.
- Each message the assistant handles is limited to 12 tool steps, which prevents endless loops.

## AI in tasks, Quick add and Home

| Where | Feature | Result |
|---|---|---|
| Task panel ✨ | **Summarize task** | 2–4 sentences on where it stands + up to 4 next steps; **add as comment** if you like. |
| | **Suggest subtasks** | 3–8 verb-first subtasks (skipping ones that exist); tick the ones you want to add. |
| | **Rewrite description**: Make clearer · Make shorter · Make friendlier · Make more formal · Fix spelling & grammar | Preview, then **Replace** or **Discard**. Replacing keeps the text but drops formatting such as lists and links. |
| | **Ask the assistant…** | Opens a new assistant conversation, pre-filled with the task's title and id; finish the question yourself. |
| Quick add | ✨ / `Alt+Enter` | *"Call Sam next Tue 3pm, urgent #sales"* → title, due date and time, priority and tags (missing tags are created). |
| Home | **Review my week** | A short Markdown review: **Wins**, **Time**, **Needs attention**, **Plan for next week**. It's built from tasks completed in the last 7 days, tracked time, overdue and upcoming tasks, and next week's calendar. |

## AI in email

The **✨ AI** menu in a thread offers:

| Item | Result |
|---|---|
| **Summarize thread** | Who wants what and by when, plus action items. |
| **Draft a reply…** | Optional instructions (*"accept, propose Thursday 2pm"*) → Compose opens with the draft and the quoted history. You edit and send. |
| **Find tasks in this email** | Up to 8 to-dos with due dates when stated. Pick a list, tick the ones you want, and they're created and linked to the thread. |
| **Sort this email / Sort again** | Classifies the thread now. |

## Inbox triage

Each sorted thread gets:

- a **category**: *Needs action* (you must do something), *Needs reply* (someone is waiting for you), *FYI*, *Newsletter*, *Notification* (automated alerts and receipts) or *Likely spam*;
- a **priority** (1 high – 3 low);
- a **one-line summary**.

Categories show as chips on threads; the chips above the list filter by category.

- **Automatic:** with *Sort new email automatically*, every new inbox email is sorted in the background. The trigger **AI classifies a new email** then lets automations act on the category (e.g. *Needs reply* → create a task).
- **Manual:** *Sort current inbox now* (Settings) or *Sort this email* (thread).

## Privacy: what is sent where

| Feature | Sent to the provider |
|---|---|
| Assistant | Your messages; the results of the tools it calls (e.g. the tasks or emails it looked up); a line with the current date and time |
| Task features | That task's title, dates, priority, description, subtasks, checklists, recent comments, and up to 2 linked threads (last 3 messages) |
| Email features | The thread's subject and last messages (6 for summaries and drafts; 3 for triage), text only |
| Quick add | The sentence you typed and today's date |
| Weekly review | Titles of completed, overdue and upcoming tasks, time totals, next week's events |
| Automation *Ask AI* | Your prompt + that task's details |

- **Nothing is sent** unless you use a feature, run an automation with *Ask AI*, or turn on automatic sorting.
- With **Local (Ollama)**, nothing leaves your PC (or your network).
- **Text from emails and tasks is marked as data**, and the AI is told not to follow instructions inside it. This defends against "prompt injection" in a malicious email.
- **Writes still need your approval.**
- Usage records (feature, model, token counts; no content) are kept locally for the cost overview and pruned after 400 days.

## Cost

You pay your provider directly; FollowUp adds nothing. Usage depends on how much you use it.

- **Typical costs:** triage and Quick add are small, cheap calls. Assistant conversations and long email threads cost the most.
- **Checking:** see **Settings → AI → Usage this month**, which estimates the cost for Claude with cache reads priced at the lower cache rate.
- **To save:** choose a smaller model (Sonnet or Haiku), lower the effort, or use Ollama.

## Behind the scenes

- **Code:** `src/main/services/ai/`
  - `providers.ts`: one interface over Claude, OpenAI and Ollama;
  - `assistant.ts`: the chat loop and approvals;
  - `tools.ts`: the assistant's tools;
  - `features.ts`: inline features, triage, weekly review and the *Ask AI* job.

  The UI is in `src/renderer/src/features/ai/`.
- **Claude:**
  - uses the official Anthropic SDK with streaming, adaptive thinking and your effort setting;
  - caches the system prompt and tools, which are frozen per conversation, to keep repeat calls cheap;
  - requests structured JSON output for features that return data;
  - for models that support it, uses a server-side fallback when a request is refused.
- **OpenAI and Ollama** use the OpenAI-compatible API (Ollama at `<server>/v1`). Structured features ask for JSON.
- **Conversation history** is stored in the provider's own message format and only ever **appended to**. This keeps prompt caching effective and keeps Claude's reasoning valid across turns. Conversations left "running" by a crash are reset to idle on start-up.
- **Tool inputs** are validated against a schema before running. A write tool runs in a database transaction, so it either fully happens or not at all.
- **Background AI** runs as jobs:
  - `ai_triage`: 3 attempts automatically, 2 when you sort the inbox manually;
  - `ai_prompt`: 3 attempts.
- **Errors** are translated into plain advice, e.g. "Your Anthropic API key was rejected", "Could not reach Ollama. Is it running?" or "Claude is rate-limiting requests…".
